### 2.2 填充率：我自己算，且发现口径不唯一

用**原始 `rectBox`**（非 t8 的 `irFillPercent`）按三种定义复算：

| 页 | 幅面 | 框面积口径 | 框并集口径 | 锚点盒口径（t8 用的） |
|---|---|---|---|---|
| MAIN | 1230×1170 | 3×200×820 / 1,439,100 = **34.2%** | 840×820 = **47.9%** | 840×680 = **39.7%** |
| MAIN 2 | 910×1170 | 2×200×820 / 1,064,700 = **30.8%** | 520×820 = **40.0%** | 520×680 = **33.2%** |

（复算脚本与结果：`t9-recompute.json`。）

**这是本轮最重要的口径发现**：同一页的「填充率」在 **30.8% ~ 40.0%** 之间摆动，取决于盒子怎么定义。
35% 这条线**跨过**了这个区间——即「是否达标」在尾页上**完全由口径决定**。
t8 选的锚点盒口径（33.2%）恰好是「不达标」的那个；框并集口径（40.0%）则达标。
任何后续结论都必须写清用的是哪一种盒子，否则 35% 没有意义。

顺带：框并集/锚点 = 1.21，与我 t7 标定的像素/IR ≈ 1.23 同量级，说明「口径差」是系统性的、可预期的。

## 4. 口径漏洞审计（④）——核心结论

### 4.1 规则本身

t7 落在 `page-budget.spec.ts` 的规则：

> `fill ≥ 0.35` **或** (`cap < 0.35` **且** `fill ≥ 0.9×cap` **且** `size ≤ minSize + 1 格`)

### 4.2 实测：`fill ≥ 0.9×cap` 在收敛页上恒真

`t9-rule-audit.mjs` 用**真实 layout 运行**复现同一块板：

```
### production (default)
  p0 MAIN   parts=54 size=1230x1170* fill=37.9% cap=37.3% min=1250x1170 -> PASS (>=35%)
  p1 MAIN 2 parts=36 size= 910x1170* fill=30.2% cap=29.6% min= 930x1170 -> PASS (ceiling clause)
```

（注：脚本里的 `parts` 是该页 `sheet.components` 的**原始条数**，含生成的旗标/端口，故为 54/36；
模块数看 `blocks`（3/2），与 spec 里 `parts=[18,12]` 的口径不同，两者不矛盾。）

`min=1250×1170` 而交付 `1230×1170`、`min=930` 而交付 `910` —— 因为测试用 `ceil` 到 10、实现用 snap，
**`minSize ≥ size` 系统性成立** ⇒ `cap ≤ fill` 系统性成立 ⇒ `fill ≥ 0.9×cap` **永远为真**。
`size ≤ minSize + 1 格` 同理也永远为真。t8 的这条保留意见**成立**，我把它从"怀疑"变成了"证明"。

### 4.3 实测：结构上限确实成了豁免通行证

同一脚本加跑 `moduleColumns: 1`（复现 t2 时代「一页一模块」的分页）：

```
### moduleColumns: 1
  p0 MCU   parts=18 size=592x1170* fill=14.1% cap=13.7% -> PASS (ceiling clause)
  p1 POWER ... 14.1% -> PASS   p2 IO ... p3 MEM ... p4 CLK ... 全部 PASS
```

**5 页、每页 14.1%，全部判 PASS**——比 35% 目标差 2.5 倍，却因为"该形状上限只有 13.7%"而被放行。
这就是"把不达标页判成达标"与"用结构上限当豁免通行证"的确凿实例。

### 4.4 那么 t8 的产物到底有没有被误判？

**没有。** 但理由不在规则里：

1. 该板的 5 个模块在 A3 上**最多只能排 2 页**（两个 band 需要 2×600+340 ≈ 1540 > 1170 高）；
2. `3+2` 是唯一均衡分法，尾页拿到 2 个模块，**已是它能拿到的最多**；
3. 所以尾页确实处在"形状 + 分页共同决定"的上限上，30.8%~40.0% 已是极限。

**但保护它的不是填充规则，而是用例里那条硬断言 `parts == [18,12]`。** 换一块板、换一次形状，
规则本身不会拦住 14.1% 的页。**结论：规则不可自足，必须补分页充分性判据。**

### 4.5 建议修法（下一轮）

1. **让上限有意义**：`minSize` 用与实现相同的 snap（就近取 10）而不是 `ceil`，使 `cap ≥ fill`，
   `90%` 条款才可能失败；或干脆把 90% 条款改成「仅在 `size > minSize`（即未收敛）时生效」。
2. **补分页充分性**：低于 35% 的页除 `cap < 35%` 外，还必须 `parts ≥ ceil(总器件/页数) - 一个 band 容量`
   （即该页拿到了均衡份额）。这样 `moduleColumns:1` 那 5 页会被拦住。
3. **常量去重**：测试目前**复制**预算常量而非 import，有漂移风险（t8 也提了）。应把
   `FITTED_MARGIN/OUTWARD/MIN_FITTED/EDGE_PAD` 以 `@internal` 导出供测试断言。

## 5. 对 t7 密度差距分析的复核（⑤）

**成立的部分**：`edgePad 170` 不可动（clearance 24）；锚点盒口径是历史可比性的定义；
收紧实验（MARGIN 60→40 + OUT_X 180→140 + OUT_TOP 200→160 → 43.5% / 35.8% / 41.9%）的结论
——"35% 并非绝对不可达，而是预算不够紧"——方向正确，且如实标注了旗标越界风险。

**不成立 / 遗漏的部分**：

1. **模块框留白被归错类**：t7 把它列为"刻意保留的取舍"，但它**对 IR 填充率毫无影响**（锚点盒口径），
   只影响像素观感。归入"取舍"会误导读者以为牺牲了指标换可读性——实际没有牺牲任何指标。
2. **遗漏水平居中**：两页右边距恒比左边距多 110 单位（140 vs 250）。这是**不花钱就能改善**的一项
   （不影响填充率、不改预算常量），且直接关系到与参考的"铺展方式"同构。
3. **`OUT_BOTTOM` 未做实验**：t7 只测了 `OUT_TOP 200→160`。模块下方没有走线时 `OUT_BOTTOM 140` 亦可收，
   按同一公式还能再挤出约 1pt；属"未穷尽"而非"不可行"。
4. **最大的遗漏是口径本身**：t7 全篇用锚点盒（37.9/30.2），而框并集口径下同一批页是 47.9/40.0——
   尾页**两种口径下结论相反**（30.8% 不达标 vs 40.0% 达标）。t7 未声明这一点，导致"是否达标"
   看起来比实际更确定。
